# Shared skills and agent setup

## One maintained skill, several clients

Edit shared bundles only under `.agents/skills/<name>/`. Each bundle has a portable `SKILL.md` with `name` and `description` and optional relative references. Start with the general [security-review](../../.agents/skills/security-review/SKILL.md) where security guidance is needed.

Codex, current Antigravity App/CLI/IDE, and Gemini CLI discover `.agents/skills/`. Claude Code discovers `.claude/skills/`; those bundles are generated byte-for-byte from the common source. Run `python3 scripts/sync_skills.py` after changing a shared skill. CI rejects drift; do not edit the generated Claude copy. Plain files avoid Windows symlink requirements. No personal/global skill installation is performed by this template.

| Client | Request the workflow | Check discovery |
|---|---|---|
| Codex | `$security-review` followed by the task, or choose it via `/skills` | Inspect the available skills in your installed client |
| Claude Code | `/security-review` followed by the task | Check its skill/command list; reload skills if needed |
| Antigravity | `/security-review` where supported, or mention it by name | Inspect Customizations / active skills |
| Gemini CLI | Explicitly ask to use `security-review` | `/skills list`, then `/skills reload` if needed |
| Grok Build | `/security-review` if listed, or ask for it by name | Inspect `/skills`; verify in the installed version |

The same approach applies to `project-customization`, `adversarial-code-reviewer`, `debugging`, and `verification`. The workflow content is identical; shortcut syntax, models, tools, permissions and approval prompts remain client-specific. Use the hyphenated name, without spaces. For older Antigravity releases that only support `.agent/skills/`, update the client or configure that legacy location separately; do not create a second independently maintained skill. Other Grok products or agents may behave differently; ask them to read `AGENTS.md` and the relevant skill file directly unless discovery is verified. Do not assume subagent capability.

Antigravity does not automatically load nested `AGENTS.md` files below an opened repository root; explicitly route it to the applicable scoped files. Its `.agents/skills.json` has a client-defined manifest format, so this template keeps its separate mirror configuration in `.agents/skill-mirrors.json`. Verify behavior in the installed client rather than assuming configuration loaded.

## Reviewer subagents

The template includes `adversarial-reviewer` and `security-reviewer` project definitions for Codex (`.codex/agents/`), Claude Code (`.claude/agents/`), Gemini CLI (`.gemini/agents/`), and Antigravity (`.agents/agents/`). Grok Build documents Claude Code agent compatibility. Request the adversarial reviewer during coding and the security reviewer on each complete code PR diff. These definitions point to the shared skills and review workflow, and do not start agents automatically. Available tools, reload behavior and permission restrictions vary; check the client's agent list. A custom role's instructions alone do not enforce a read-only sandbox. If a client cannot discover or delegate these roles, use the shared role prompt in a genuinely separate session and report the result or a pending gate.

Some supplied roles have read/search tools but no Git shell access. The parent must provide the complete, untruncated staged or PR diff, revisions, and relevant context, or arrange another independent reviewer that can inspect them. The reviewer must report when it cannot verify the exact snapshot or inspect a changed file; an incomplete review cannot pass the gate.

Conditional `migration-reviewer` and `accessibility-reviewer` definitions use the same client locations for data changes and UI work. Additional portable skills are `dependency-maintenance`, `release-recovery`, `data-migration`, `accessibility-review` and `budget-planning`; invoke them by the same client-specific skill mechanism, or read their `SKILL.md` directly. Budget estimates must include agent reviews/API/tool and hosting usage, not just application compute, and verify current billing terms.

## Initialize every checkout

Requires Git and Python 3.10+. From the root run:

```bash
python3 scripts/bootstrap.py
python3 scripts/verify.py
```

On Windows use `py -3` or `python` instead of `python3` if that is your installed launcher. Hooks work through Git's shell and use the same Python policy scripts. Setup refuses to replace a different effective `core.hooksPath`, including inherited global/system configuration. Repeat bootstrap in each new clone; worktrees using a shared hooksPath must share these policy files.

Start at [AGENTS.md](../../AGENTS.md), inspect Git status and branch, read the [context map](../context/README.md), then the assigned task and scoped instructions. Use the [handoff template](../templates/handoff.template.md) to record actual results and the next action before switching agents.

`CLAUDE.md` imports the shared contract. Gemini's project settings select `AGENTS.md`. Current Antigravity surfaces load the root `AGENTS.md` as an always-on workspace rule. Scoped context below the opened workspace may differ by client; follow the context map rather than assuming identical recursive discovery. Context discovery and skill discovery are separate mechanisms.

## Controls and limitations

The shared contract does not grant tool permissions. Claude has a project-local deny baseline for private environment files and common destructive Git commands; it also denies `.env.example` under the wildcard. Other clients require their own runtime permission policies. Git hooks add tool-independent checks after bootstrap; `--no-verify`, changed Git configuration, native GitHub APIs or another unconfigured clone can bypass them. Only activated server-side rules can reject direct protected-branch updates independently of the client.

The included scanner checks file names and a few high-confidence credential patterns. It is not a comprehensive secret scan, SAST, dependency audit, penetration test or security certification. Add application-specific checks once the project's stack exists. Do not claim the application passed tests while this is an uncustomized template.

## Imported skills and applicability

[pr-description](../../.agents/skills/pr-description/SKILL.md) is imported verbatim from
`pr description writer.md`. Use `/pr-description` in clients with slash invocation,
or `$pr-description` in Codex. Source/destination already given by the user or the
repository's PR flow do not need to be asked again. Its local `PR_DESCRIPTION.md`
draft is ignored by Git. Publishing a PR still follows the user's authorization.
Shared skills and their resources are mirrored identically for Claude by the existing sync script.
